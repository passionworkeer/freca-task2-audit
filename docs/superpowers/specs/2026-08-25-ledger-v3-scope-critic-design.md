# Ledger v3：证据层级与冲突裁判设计

## 目标

在 34 条 confirmed Gold 上分别检验两种通用改进：证据主体/层级约束，以及直接审查两份 LLM 结论的冲突裁判。两者均不读取 Gold、案例编号或 CP 的人工答案。

## 方案

### A. 证据主体与层级约束

裁决提示词增加通用约束：

- 已标记为外部主体的事实不能支持当前主体；全局身份矛盾是质量风险，不能自动推翻来源与主体明确、可原子独立的事实。
- 对场所设计、建筑、设施或设备能力的要件，日常执行事件、清洁瑕疵或程序文本不能单独证明设计不合规；反证必须直接指向该设计/设施要件。
- 对持续执行、货物路线、批次流转和放行类要件，程序仍不足，必须有同主体的实际记录。
- `0` 的反证必须与当前法规要件、当前主体及事实层级直接对应。

这只改变模型如何使用已选事实，不隐藏矛盾、不扩大检索，也不改变 v2 的 N/A 硬门。

### B. 冲突理由裁判

当 primary 与 independent review 均通过门禁但 verdict 不同，Critic 获得：

- 紧凑法规 rubric 与事实包；
- primary/review 的 verdict、适用性、理由、引用和 gate 摘要。

Critic 逐条检查引用是否支撑理由、主体和事实层级是否匹配，并只返回 `primary` 或 `review`。它不能产出新 verdict、引用或事实。若 Critic 阻断、格式无效或选择门禁失败的结论，则保留既有协调结果。

## 运行

- `ledger-evidence-scope-gold-v3`：仅启用 A。
- `ledger-conflict-critic-gold-v3`：仅启用 B，沿用 v2 默认裁决与二审。

两条均以独立目录跑 34 条 Gold，使用 MiniMax-M3、`max-workers=1`，然后与 v1/v2 统一比较。

## 成功标准

1. A 的单元测试保证非设计类事故不能作为纯设计反证，外部主体事实不能支撑当前主体，且执行型要件仍要求实际记录。
2. B 的单元测试保证 Critic 只能选 primary/review，且模型错误不会覆盖已有协调结论。
3. 每条 v3 的 coverage 为 100%、终态失败为 0 后才按 agreement 竞争；若没有超过 79.4%，保留最佳 v2，不扩展任务集。
