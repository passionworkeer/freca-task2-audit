# Task2 Gold 基线与农场能力迁移设计

## 目标

将团队已确认的人工 CP 结论冻结为可版本化的 Gold 基线。后续任一方法在相同 Case、CP、法规输入和模型配置下运行，并用同一评估器比较最终 verdict 与 Gold 的一致性。同时保留证据链与调用成本，避免只凭 verdict 相似度选择方案。

## 基线选择

`Task2-agent-pipeline` 是唯一的实验代码基线。组织仓库的 `Task2` 与其没有共同 Git 历史，不能直接合并；`Task2` 中的农场 Case 输入、解析或检索能力只按明确接口选择性迁入。

## Gold 数据边界

- Gold 使用显式的 `(case_id, cp_id) -> verdict` 记录。
- 每条记录附带：人工共识来源、裁决原则摘要、是否已确认。
- 仅 `confirmed=true` 的记录参与 verdict 一致率。
- 仍有争议的 CP24、CP26，以及待补的 CP17、CP19，先可记录但不计入评估分母。
- `N/A` 与 `0` 是不同标签；评估器不得把“未证明”自动转换为“不适用”。

## 评估输出

评估器读取某次运行的最终 verdict，并对齐 Gold，输出：

- 总体和逐 CP 的一致率；
- 混淆矩阵及每条不一致记录；
- Gold 覆盖数、缺失输出数和额外输出数；
- 若运行产物提供，附带每条的证据引用和模型调用数量/成本。

Verdict 一致率是首要排序指标；证据链正确性和成本作为并列诊断项，而不是被静默折算进一致率。

## 农场能力迁移边界

先只评估并迁入能转换为现有 `freca` 输入契约的内容：Case 文件定位、解析或预构建检索材料。不得引入另一套 `backend/` 执行入口、状态文件或独立输出格式。每一项迁移需有针对现有 `freca` 接口的测试。

## 验收标准

1. 用已确认的人工结论运行评估，结果可复现且逐项可追溯。
2. 不确认或有争议的条目不进入准确率分母。
3. 评估可比较多个运行 ID，不改变原有最终 verdict。
4. 所有新增测试与现有测试通过。
5. 农场能力仅在其输入输出与现有基线兼容时迁入，并保留来源记录。
