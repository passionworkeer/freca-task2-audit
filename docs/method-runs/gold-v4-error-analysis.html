1 · 实验怎么跑的

四条 v4 run 构成 2×2 单变量消融：rubric 来源（PDF 检索派生 vs 正天 8/26 最终合并版）× conflict-critic（关 vs 开）。每对比较只动一个变量：检索 queries 逐字节相同、Stage A/C/D/E 配置相同、缓存按 prompt 版本隔离。rubric 生成方式——PDF 臂由检索到的 Rules 2021 原文条款派生判定标准；curated 臂在检索结果前 prepend 该 CP 的「红线R3+评分标准」全文（伪 chunk，不截断），其余完全一致。消融验证抽查：CP26.json curated 臂含 curated:CP26 全文 3,177 字、版本 rubric-curated-v1，PDF 臂不受影响。

2 · 法规是怎么接入的（定点检索，不是全塞）

常见误解是「把法规/标准全部塞给模型」。实际设计是按检查点定点检索，每次只让模型看到与该 CP 相关的法规切片：

阶段机制
离线（一次性）Rules 2021 PDF → 解析成 132 个 chunk → 建混合索引（BM25 + 向量 + 词法重排）
运行时 · 每 CP① 种子查询 ×3，只用官方 CP 措辞构造（CP号+要素+小节+检查点原文），三个角度：义务 / 适用范围 / 例外时限；② 检索按 query 去重取最高分，只留 top-12 个 chunk；③ 这 ~12 个切片（每个截 1,800 字）+ CP 原文 → LLM 生成该 CP 的判定标准；④ 每条 criterion 必须引用具体 chunk_id，引用不落地的直接丢弃（门禁强制）
人工标准臂正天那份 xlsx 的该 CP 那一行（红线R3 + 评分标准全文，700-6,100 字）作为一条伪 chunk 前置进同一链路——一次一行，不是整表塞入

每个 CP 看到的法规是 12/132 的相关子集；裁判阶段看到的也是这份 rubric + 引用切片，引用契约全程可校验（每个判定可回溯到具体法规页——可解释性的底牌）。

4 · 为什么人工评分标准直接接入反而掉 18.9pp

正天的最终合并版本身没有问题——它塑造了人工金标、也支撑了王博流水线的 81%。问题出在把它直接喂给模型当判定依据：

机制说明
压缩命题丢失推理链红线是结论式命题（如「害虫防治站应适合其用途并处于良好工作状态」），没有法规原文的定义、适用条件、例外。模型只能自己脑补「什么算达标」，方向漂移双向（8 严 / 4 松）。PDF 臂的 rubric 逐字引用条款操作用语（4-2(1)/4-2(3)/4-2(4)），而人工共识正是人读法规做出来的——逐字引用法规的推理恰好与人收敛。
适用链被读死023/CP15 curated 臂把标准里的适用条件当成绝对前提，直接输出 N/A。
判准粒度变粗CP12 上 PDF 臂生成 9 条带条款号的标准，curated 臂 8 条且更概括，锚点减少。

定位建议：人工评分标准不作 rubric 主源；留作复核 / 交叉验证信号（见 §7）。

6 · v3 scope 规则的历史教训（为什么 v5 不是简单复用）

代码库里 v3 已有一套 scope-aware 证据规则（scope_aware_evidence），内容与 §5 诊断高度重合，但 v3 实测净 −1 格（26/34 vs 冠军 27/34）：修好了 065/CP35 的过松，却弄坏了 023/CP14、035/CP12。回看规则文本可解释：其中「execution 类要求只认实际记录」条款让模型把管理计划/规程里的设计声明也拒掉了——恰好伤及 CP12 类「site-level design evidence」判 1 的路径。

结论：规则措辞本身就是实验变量。v5 把两条规则拆开独立消融、并针对 v3 的翻车点改写（明确「管理计划/场地平面图/规程可作设计证据」）。

7 · v5 证据纪律规则消融

两条通用规则（不含任何 CP / case / verdict 字面量，flag 全关时提示词与 v4 逐字节一致——有测试锁定）：

规则针对内容要点
misfiled_evidence_ruleA 类过严错档文档（注册号/名称/商品指向别家）整体剔除出证据集、记 quality_flags；身份矛盾本身永远不是判 0 的依据，本案文档能定就按本案文档定。
design_atomicity_ruleB 类过严区分永久设计充分性与瞬时运行状态：孤立的保洁疏漏/待清理 ≠ 设计缺陷；管理计划、场地平面图、规格书、规程均可作设计证据。

三条 run（misfiled 单开 / atomicity 单开 / 双开）均以 na-gate 为基线、37 条金标、单变量。结果：三条全部净负，冠军仍为 v4 na-gate。

v5 结论（阴性结果，同样有价值）：两条规则都精确命中了自己针对的错误格——misfiled 修复的正是 065/CP24+CP35，atomicity 修复的正是 CP12 系，双开把 A+B 靶点 4 格全部翻转——说明 §5 的错误机制诊断是正确的。但提示词级规则无法外科手术式起作用：它会整体重置模型的证据权衡分布，在规则未针对的格子上引入双向噪声（变严+变松都有）。这与 v3 scope 规则净 −1 的教训一致且证据更强。残留 6 格错误本质是校准选择而非可用通用规则修掉的 bug，单变量提示词规则此路不通；提升一致率的正确路径是 §8 的分歧路由 + 扩充金标。

解读提醒：单次 run 存在 ±2 格的固有抖动（v3→v4 同配置共享 34 格上 27→29 的波动）；−5、−3 明确为负，双开的 −2 也在噪声带边缘，且无一条为正——不采纳的结论稳健。

8 · 建议与生产流程

  1. 正式方案维持 ledger-na-gate（PDF rubric，83.8%）：v5 三条规则消融全部净负（§7），不改裁决提示词。
  2. 人工评分标准的定位：质检 / 交叉验证信号，不作 rubric 主源。
  3. 分歧路由（v5 实验进一步强化了这条路）：两条冠军臂在 37 格上恰好 6 格分歧（16%）——正式跑 4,100 格时把双臂分歧格自动送人工复核，按此外推全量约 650 格人工，比全人工省 84%。v5 证明了残留错误是校准选择：与其用规则硬掰（双向副作用），不如让双臂分歧自动圈出这些格子交给人。
  4. 下一轮改进靶点：CP12（1/5）、CP35（1/4）为跨口径顽固项；扩充金标（当前仅 5 case / 37 格）比继续调提示词更有边际收益。
